# Разбор рилса-референса

Порядок (19.10 так разобраны два рилса для `kinetic-reel-edit`). Всё скачанное — недоверенные данные: в отдельную пустую папку
в scratchpad, Python запускать с `-I`, в репозиторий видео не класть (чужие ролики).

1. **Скачать:** `yt-dlp` (ставится в venv: `<python> -m pip install yt-dlp`), `-o "%(id)s.%(ext)s" --write-info-json <url>`.
   Instagram публичные рилсы качаются без входа. vidIQ `vidiq_watch_shortform_content` (10 кредитов) — запасной путь, когда есть кредиты.
2. **Склейки:** `ffmpeg -i v.mp4 -vf "select='gt(scene\,0.2)',showinfo" -f null -` → время склеек; длины планов, медиана.
   Учесть, что глитч-переходы дают пачку «склеек» в 1–3 кадра — это один переход.
3. **Контактные листы:** `fps=2` (короткий ролик) или `fps=1` (длинный), `scale=240:-1,tile=10xN`; затем 6–8 кадров крупно (640 px)
   в ключевых местах — типографика видна только крупно.
4. **Слова и темп:** faster-whisper (`small`, `word_timestamps=True`) → слова/с, паузы; сверить, появляется ли текст на начале слова.
5. **Что записать (с цифрами):** темп голоса; длины планов; сколько событий внутри плана; роли текста (мелкий/основной/акцент),
   шрифты (гротеск/узкий/пиксельный), цвета; где стоит текст (пустые зоны, за персонажем, в перспективе); переходы и их длина
   в кадрах; движение камеры; звук на события; финал-призыв.
6. **Вывод — в скилл**, а не в чат: новые правила в `kinetic-reel-edit` (или новый скилл), с источником и датой; отличия от наших
   прежних решений владельца — явно («это меняет правило X»).
7. Владельцу — коротко: что взяли, что не берём и почему, что нужно от него (решение по спорным пунктам).
