# Kwork AI-агент

Агент каждый день сам:

1. **Исследует нишу в интернете** (Claude + веб-поиск): новые инструменты, что
   покупают на Kwork/FL.ru/YouDo/Upwork, цены, слова, которыми заказчики
   описывают задачи, незанятые услуги. Всё копится в `data/knowledge_base.json`,
   отчёты — в `data/research/`.
2. **Развивается**: переписывает свою стратегию объявлений (`data/strategy.md`)
   с учётом новых знаний и результатов публикаций. История версий —
   `data/strategy_history/`. Ещё он оставляет себе вопросы для завтрашнего
   исследования, так что каждый день копает глубже, а не по кругу.
3. **Пишет уникальные объявления**: берёт неиспользованные идеи услуг,
   ключевые слова и стратегию, проверяет длину полей, отсутствие контактов и
   ссылок (Kwork это запрещает) и сходство с уже созданными кворками. Похожие
   объявления отбрасывает и пишет заново.
4. **Публикует на Kwork**: открывает браузер (Playwright) и сам заполняет
   форму «Создать кворк». Готовых селекторов в коде нет: на каждом шаге Claude
   видит элементы страницы и скриншот и решает, что заполнить и куда нажать,
   поэтому публикация не ломается при изменении вёрстки Kwork. Обложку
   660×440 агент рисует сам.

## Запуск одной командой

Нужны Python 3.10+ и git. На своём компьютере:

```bash
git clone https://github.com/vitoskk-esd/123.git && cd 123
pip install -r requirements.txt
python -m playwright install chromium
python -m kwork_agent setup
```

`setup` спросит ключ Anthropic API, откроет браузер для входа в Kwork и — если
установлен [GitHub CLI](https://cli.github.com) (`gh auth login`) — сам запишет
секреты в репозиторий и запустит первый прогон. Без `gh` он подскажет, что
вставить в настройки GitHub вручную.

## Быстрый старт (локально)

```bash
pip install -r requirements.txt
python -m playwright install chromium
cp .env.example .env            # впишите ANTHROPIC_API_KEY
python -m kwork_agent login     # откроется браузер — войдите в Kwork, нажмите Enter
python -m kwork_agent daily     # полный цикл
python -m kwork_agent status    # что накопилось
```

Отдельные этапы: `research`, `reflect`, `generate 5`, `publish`.

**Первый запуск делайте с `KWORK_DRY_RUN=1`** (так стоит в `.env.example`):
агент заполнит форму, но не отправит кворк на модерацию. Посмотрите скриншоты в
`data/screenshots/`, и если всё заполняется правильно — поставьте
`KWORK_DRY_RUN=0`.

## Полная автоматизация через GitHub Actions

Workflow `.github/workflows/kwork-agent.yml` запускается каждый день в 08:17 МСК,
выполняет весь цикл и коммитит обновлённую базу знаний и стратегию в репозиторий.

1. Смёржите эту ветку в ветку по умолчанию (GitHub запускает расписание
   только оттуда).
2. В **Settings → Secrets and variables → Actions → Secrets** добавьте:
   - `ANTHROPIC_API_KEY`
   - `KWORK_STATE_B64` — сохранённая сессия Kwork. Получить её:
     `python -m kwork_agent login`, затем `base64 -w0 data/kwork_state.json`
     (на macOS: `base64 -i data/kwork_state.json`).
   - по желанию `KWORK_LOGIN` и `KWORK_PASSWORD` — запасной автовход, если
     сессия протухнет (не сработает, если Kwork покажет капчу).
3. В **Variables** задайте `KWORK_DRY_RUN=0`, когда будете готовы публиковать
   по-настоящему (по умолчанию `1`).
4. Запустить вручную: вкладка **Actions → Kwork AI agent → Run workflow**.

Скриншоты и логи каждого запуска сохраняются в артефактах workflow.

> ⚠️ Если репозиторий публичный, база знаний и тексты объявлений будут видны
> всем. Секреты (ключ API, сессия Kwork) в репозиторий не попадают.

Вместо GitHub Actions можно запускать на своём сервере через cron:
`17 8 * * * cd /path/to/repo && python -m kwork_agent daily`.

## Сколько объявлений в день

Первый день — 15, дальше каждый день на 3 больше (18, 21, 24…) до 45.
План растёт, только если вчера Kwork принял хотя бы 70% публикаций: если
начались отказы (капча, лимит кворков, ошибки формы), план замирает, пока всё
не наладится. Текущий план и история — в `data/ramp.json`
(`python -m kwork_agent status`). Всё меняется переменными ниже — в GitHub это
**Settings → Secrets and variables → Actions → Variables**.

Одна публикация через браузер занимает несколько минут, а GitHub даёт прогону
максимум 6 часов, поэтому публикация останавливается через 5 часов; что не
успело выйти, публикуется на следующий день в счёт плана.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `KWORK_START_PER_DAY` | 15 | Объявлений в первый день |
| `KWORK_DAILY_INCREASE` | 3 | На сколько план растёт каждый день |
| `KWORK_MAX_PER_DAY` | 45 | Потолок в день |
| `KWORK_RAMP_SUCCESS_RATIO` | 0.7 | План растёт, только если вчера прошло ≥ 70% публикаций |
| `KWORK_PUBLISH_TIME_BUDGET_MIN` | 300 | Сколько минут максимум публиковать за прогон |
| `KWORK_DRY_RUN` | 0 | 1 — не отправлять на модерацию |
| `KWORK_NICHE` | ИИ-автоматизация, контент-заводы… | Описание ниши |
| `KWORK_AGENT_MODEL` | `claude-opus-5` | Модель Claude |
| `KWORK_TITLE_MAX`, `KWORK_DESCRIPTION_MIN/MAX`, `KWORK_PRICE_MIN/MAX` | 80, 300/1200, 500/50000 | Ограничения полей — сверьте с текущими правилами Kwork |
| `KWORK_AGENT_SCREENSHOTS` | 1 | Показывать Claude скриншоты при заполнении формы |
| `KWORK_HEADLESS` | 1 | 0 — видеть браузер во время работы |

## Важно знать

- **Правила Kwork.** Kwork вручную модерирует каждый кворк и ограничивает
  число активных кворков у продавца. Массовая публикация похожих объявлений —
  прямой путь к отклонениям или блокировке аккаунта. Проверка уникальности,
  пауза между публикациями и остановка роста плана при отказах снижают риск,
  но не убирают его.
- **Капча и вход.** Если Kwork покажет капчу или попросит код подтверждения,
  агент остановит публикацию (статус `blocked`), а объявление останется в
  очереди. Тогда заново выполните `login` и обновите `KWORK_STATE_B64`.
- **Стоимость.** Расход идёт на API Claude: исследование с веб-поиском,
  генерация и браузерный агент, который делает до ~45 шагов на кворк.
  Точная сумма зависит от объёма, следите за расходами в консоли Anthropic.
  Чтобы сэкономить, поставьте `KWORK_AGENT_SCREENSHOTS=0`.
- **Статусы объявлений** (`data/listings.json`): `draft` — ждёт публикации,
  `submitted` — отправлено на модерацию, `draft_saved` — заполнено в режиме
  проверки, `failed` — не получилось (3 попытки, затем пропускается).
